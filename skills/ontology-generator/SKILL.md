# 本体模型生成器 (Ontology Generator)

## 概述

本 Skill 基于本体论（Ontology）方法论，帮助用户完成两类核心任务：

1. **从业务场景生成本体 Schema** — 用户描述业务领域和需求，自动生成规范化的实体类型、属性定义、关系定义
2. **将已有 Schema 转换为可执行格式** — 将 xlsx 格式的 Schema 转换为 Neo4j Cypher、OWL/RDF、JSON-LD 等

## 工作流程

### 第一步：理解用户意图

判断用户需要哪种服务：

- **场景 A：从零生成** — 用户描述业务场景，需要从头设计本体模型
- **场景 B：格式转换** — 用户已有 xlsx Schema 文件，需要转换为其他格式
- **场景 C：优化已有模型** — 用户有现成的本体模型，需要评审和改进

### 第二步：场景 A — 从业务场景生成本体 Schema

#### 2.1 领域分析

向用户收集以下信息（不必一次问完，可以在过程中逐步澄清）：

- **业务领域**：设备管理、故障诊断、供应链、医疗、金融等
- **核心业务对象**：需要管理的主要事物（设备、部件、故障、工单等）
- **关键业务流程**：对象之间如何互动（检查流程、维修流程、诊断链路等）
- **数据使用场景**：这个本体模型最终用在哪里（知识图谱查询、智能问答、数据分析等）

#### 2.2 本体设计方法论

遵循以下本体论原则进行建模：

**实体识别原则：**
- 从业务场景中提取名词性概念作为候选实体
- 每个实体应有明确的语义边界，不与其他实体大量属性重叠
- 实体命名采用 PascalCase 英文名 + 中文括注的方式，如 `Equipment（设备）`
- 区分实体层级：核心实体（业务主体）、辅助实体（描述信息）、枚举实体（分类标准）

**属性设计原则：**
- 每个实体的属性应能唯一描述该实体的一个实例
- 必须包含 ID 属性（命名规范：`<entity_name>_id`）
- 明确标注：属性名称（snake_case）、是否可为空、默认值、属性描述
- 枚举型属性需在描述中列出所有可能值

**关系设计原则：**
- 关系应反映业务领域中实体间的真实交互
- 每个关系包含：关系名称、描述、起点实体、终点实体、关系属性
- 关系属性应量化或描述关系的具体特征（如置信度、优先级、层级）
- 识别以下类型的关系：
  - **结构关系**（组成、包含、属于）
  - **流程关系**（触发、执行、产生）
  - **因果关系**（导致、表现为、解决）
  - **引用关系**（参考、记录于、遵循）

**链路设计原则：**
- 将相关的实体和关系组织成有意义的业务链路
- 每条链路应反映一个完整的业务流程或分析路径
- 命名格式：`X链路：核心路径 A → B → C`

#### 2.3 输出生成

阅读 `references/schema_patterns.md` 了解两个参考场景的详细模式，然后按照用户选择的格式生成输出。

**默认输出 Excel (.xlsx) 格式**，包含三个 Sheet：

1. **实体与属性定义** — 列：实体类型名称、描述、属性名称、是否可为空、默认值、属性描述
2. **关系与属性定义** — 列：关系类型名称、关系描述、起点实体、终点实体、关系属性名称、是否可为空、默认值、属性描述
3. **实体关系图** — 文字描述的链路图，组织核心链路和路径说明

生成 xlsx 时，阅读 xlsx Skill 的 SKILL.md 获取 Excel 文件创建的最佳实践，并使用 `scripts/generate_xlsx.py` 辅助脚本。

**其他可选输出格式**，阅读 `references/output_formats.md`：

- **Neo4j Cypher** — 节点标签、约束、索引、关系创建语句
- **OWL/RDF (Turtle)** — 标准 Web 本体语言格式
- **JSON-LD** — 链接数据 JSON 格式
- **Mermaid ER 图** — 可视化实体关系图

### 第三步：场景 B — Schema 格式转换

1. 读取用户提供的 xlsx 文件（使用 pandas 解析）
2. 提取实体定义、属性定义、关系定义
3. 按用户指定的目标格式生成输出
4. 阅读 `references/output_formats.md` 获取各格式的具体生成规则

### 第四步：场景 C — 模型优化

1. 读取现有模型
2. 按照本体论方法论评审：
   - 实体边界是否清晰
   - 属性是否完整且无冗余
   - 关系是否反映真实业务语义
   - 链路是否覆盖所有核心业务流程
3. 提出改进建议并生成优化后的模型

## 质量检查清单

生成本体模型后，执行以下验证：

- [ ] 每个实体都有唯一 ID 属性
- [ ] 所有关系的起点和终点实体都已定义
- [ ] 枚举属性的所有可能值都已列出
- [ ] 没有孤立实体（至少参与一个关系）
- [ ] 链路覆盖用户描述的所有核心业务流程
- [ ] 属性命名一致（snake_case）
- [ ] 实体命名一致（PascalCase + 中文括注）

## 参考文件说明

- `references/schema_patterns.md` — 两个完整参考场景的本体模式提取，在设计新本体时必读
- `references/output_formats.md` — 各输出格式（Cypher、OWL、JSON-LD、Mermaid）的生成规范
- `scripts/generate_xlsx.py` — 从 Python 数据结构生成标准格式 xlsx 的辅助脚本
